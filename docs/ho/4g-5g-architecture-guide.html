How to use this guide

This is the long-form reference for the mobile network architecture that a CDA design has to understand: the 4G Evolved Packet System (EPS) and the 5G System (5GS), the IMS service core that sits on top of both, and the identifiers, procedures and interfaces that produce communications data. It is organised so that each part can be read alone. Part I is orientation; Parts II and III are the 4G and 5G architectures in depth; Part IV covers what is common to both (IMS, identity, QoS, mobility, charging, lawful intercept); Part V is the CDA view. The abridged edition carries the same structure in a tenth of the space.

Part I — Orientation

1.1 Generations in one paragraph

2G and 3G carried voice as circuits and data as an add-on. 4G (LTE, standardised from 3GPP Release 8, 2008) is all-IP: there is no circuit domain, every service including voice is a packet flow, and the core network — the Evolved Packet Core — is a set of gateways and a control node. 5G (Release 15 onward, 2018) keeps the all-IP model but rebuilds the core as a set of cloud-native network functions talking over service-based interfaces, separates user plane from control plane completely, and adds network slicing and a new radio. Voice in both generations is delivered by the IMS, which sits above the core and is the same system for 4G, 5G, Wi-Fi calling and fixed broadband.

1.2 The three planes

Every element in this guide lives on one or more of three planes, and almost every architectural argument comes down to which plane a piece of data is on.

PlaneWhat travels on it4G elements5G elements
Control plane (signalling)Attach, authentication, session set-up, mobility, policy decisionsMME, HSS, PCRF, the control side of SGW/PGWAMF, SMF, UDM, AUSF, PCF, NRF, NSSF, NEF
User plane (traffic)The subscriber's IP packets — web, video, and the voice media of an IMS callSGW-U, PGW-U (after CUPS), eNB user planeUPF, gNB user plane
Management planeConfiguration, performance, fault, orchestrationOSS/BSS, EMSOSS/BSS, NFV MANO, SMO

For communications data the control plane is what matters: it is where identities, times, cells and session events are visible. The user plane carries content and, after CGNAT, the address translations that resolution depends on. The management plane is where change happens, usually without telling anyone downstream.

1.3 Reading a 3GPP diagram

Boxes are functions, not necessarily machines: a vendor may combine several in one product (an HSS+UDM, an SGW/PGW combined node) or split one across many instances. Lines are reference points named with a letter and number (S1, S6a, N2, N11) and each carries a defined protocol. In 4G the reference points are point-to-point; in 5G the control-plane functions also expose services (Namf, Nsmf) on a shared bus, and the N-numbered reference points are a logical view over those services. Whenever a vendor says 'our platform does X', ask which 3GPP function and which reference point they mean.

2.2 The access network: E-UTRAN

E-UTRAN is the radio access network and consists of eNodeBs (eNBs) — the base stations — and nothing else. There is no controller node (the 3G RNC is gone); the eNB does radio resource management, scheduling, handover decisions, encryption of the radio link and admission control itself. eNBs connect to each other over X2 for handover and interference coordination, and to the core over S1.

ConceptMeaning
CellOne sector of one eNB on one carrier frequency. Identified globally by E-UTRAN Cell Global Identifier (ECGI = PLMN + 28-bit cell identity). This is the 4G location granularity.
Tracking Area (TA)A group of cells. The UE in idle mode is known to the core only at TA level (Tracking Area Identity, TAI); paging goes to all cells in the TA list.
RRCRadio Resource Control — the protocol between UE and eNB that establishes the radio connection. RRC_IDLE and RRC_CONNECTED are the two states that matter.
Carrier aggregation, MIMOCapacity features; irrelevant to CDA except that a UE may be served by several cells at once and the primary cell is the one reported.
eNB typesMacro, small cell, home eNB (femto). A femto cell's reported location is the device's registered address, which may be wrong.

2.5 Bearers and QoS

The EPS bearer is the unit of QoS. Every UE with an active PDN connection has at least one default bearer per APN, created at attach, which is non-guaranteed-bit-rate and carries general traffic. Dedicated bearers are added for flows needing specific treatment; the one that matters is the voice bearer the IMS requests for a call.

An APN (Access Point Name) names a PDN connection. VoLTE devices attach to at least two: the 'ims' APN (QCI 5 default bearer, IMS signalling) and the 'internet' APN. Each APN gets its own UE IP address, so a device has at least two addresses at once — which is why 'the UE's IP address' is never a complete identifier.

Tracking area update and paging

In idle, the UE moves freely within its TA list and reports only when it leaves it or a periodic timer fires. The core therefore knows an idle UE's location only at TA granularity and only as at the last update. When traffic arrives for an idle UE, the MME pages across the TA list; the UE answers from one cell and that cell is then known. This is the mechanism behind 'location is occasional, not continuous'.

Every handover updates the serving cell known to the eNB, but only S1 handovers and path switches are visible to the core as events. Cell changes within a connected session are therefore under-reported in core records; the P-Access-Network-Info header on the next IMS signalling message is often the better location source.

2.7 CUPS: separating control and user plane in 4G

Release 14 introduced Control and User Plane Separation: SGW and PGW each split into a control part (SGW-C, PGW-C) and a user part (SGW-U, PGW-U) linked by Sx (PFCP). This lets user-plane nodes be placed near the edge and scaled independently. It is the direct ancestor of 5G's SMF/UPF split, and in mixed estates the same physical UPF often serves as PGW-U.

3.3 The core: 5GC and the service-based architecture

The 5G core is designed cloud-native. Every control-plane function is a network function (NF) that offers services over HTTP/2 REST APIs on a common bus — the Service-Based Interface (SBI). Functions find each other through the NRF rather than through configured point-to-point links. The 4G MME is split into the AMF (mobility, access, NAS security) and the SMF (sessions); the SGW/PGW split into SMF (control) and UPF (user plane); the HSS becomes UDM plus UDR (data) plus AUSF (authentication); the PCRF becomes the PCF.

Most UK operators have run NSA for years and are moving to SA progressively. A retention design must therefore expect 'a 5G subscriber' to produce 4G-shaped records for some time, and both shapes concurrently during migration. Ask the programme which option each site, and each device class, is on.

3.6 PDU sessions and QoS flows

The 5G equivalent of an EPS bearer plus PDN connection is the PDU session: a connection to a Data Network Name (DNN — the 5G APN) with one or more QoS flows inside it, each identified by a QoS Flow Identifier (QFI) and governed by a 5QI value. Unlike 4G, one PDU session carries many flows in a single N3 tunnel; QoS differentiation is per flow, not per tunnel. PDU session types: IPv4, IPv6, IPv4v6, Ethernet, Unstructured.

5QIEquivalent QCIUse
11Conversational voice (VoNR media)
22Conversational video
55IMS signalling — the 'ims' DNN default flow
6-96-9Internet traffic tiers
80-86(new)Low-latency and V2X; delay-critical GBR

Session and Service Continuity (SSC) modes 1, 2 and 3 define whether the UE keeps its IP address when the anchor UPF changes. Mode 1 (keep) is the 4G behaviour; modes 2 and 3 release and re-allocate, which means a 5G UE's IP address may change mid-session in ways 4G never did — a new wrinkle for IP-to-subscriber resolution.

3.7 Network slicing

A slice is a logical end-to-end network — its own set of NF instances, UPFs and RAN resources — identified by S-NSSAI (slice/service type plus optional differentiator). Typical SSTs: eMBB (1, broadband), URLLC (2, low latency), mIoT (3, massive IoT), V2X (4). A UE may be registered to several slices at once; each PDU session belongs to exactly one. For CDA the consequences are that a subscriber's sessions may be anchored on different SMF/UPF sets depending on slice, that slice membership is itself a subscription attribute (entity data), and that a sliced IoT population will behave nothing like handsets in volume.

3.8 Identity and privacy in 5G

5G fixed the long-standing 4G weakness that the IMSI is sent in clear on first attach. The permanent identifier is now the SUPI (Subscription Permanent Identifier — in practice an IMSI or a network access identifier), which is never sent over the air; the UE sends a SUCI (Subscription Concealed Identifier), an encryption of the SUPI under the home network's public key, which only the home UDM can decrypt. The temporary identifier is the 5G-GUTI, re-allocated frequently. The device identity is the PEI (Permanent Equipment Identifier — the IMEI). The externally visible subscriber identity is the GPSI (Generic Public Subscription Identifier — the MSISDN or an external ID).

Voice on 5G: VoNR and EPS Fallback

VoNR (Voice over New Radio) is an IMS call with its media on a 5QI-1 QoS flow in a PDU session to the 'ims' DNN — the same IMS, the same P-CSCF, a different access. Where VoNR is not yet enabled on a cell, the network uses EPS Fallback: on receiving the IMS call set-up, the gNB redirects or hands the UE over to LTE before the QCI-1 bearer is created, and the call completes on 4G. The IMS registration and the INVITE were on 5G; the dedicated bearer, the media and the release are on 4G. A single call therefore spans two cores and two record sets.

Part IV — The layers common to both

4.1 IMS: the service core above the packet core

The IP Multimedia Subsystem is access-independent: the same core, the same identities and the same records serve a call made over 4G, 5G SA, Wi-Fi calling (via ePDG or N3IWF) or fixed broadband. It connects to the packet core in exactly two places: the P-CSCF reaches the UE through the 'ims' APN/DNN, and the P-CSCF asks the PCRF/PCF (Rx/N5) for a media bearer or QoS flow. 4.3 Charging

Both cores produce charging records: the 4G PGW generates per-bearer records over Gz (offline) and Gy (online); the 5G SMF reports to the CHF over Nchf. IMS nodes generate their own over Rf/Ro (4G) or Nchf

(5G), correlated by ICID. The charging record is the most complete pre-existing consolidated view of a session, which is why programmes are tempted to retain it — and why the CDA course warns that it reflects what is billable, changes with the tariff, and is consolidated late.

Points of Interception (POIs) exist in the AMF, SMF, UPF, UDM, SMSF and in the IMS CSCFs and application servers. LI_X2 carries intercept-related information (events — the communications-data-shaped part); LI_X3 carries content. The same architecture is reused for communications data acquisition, which is the course's point that separation between content and CD is administrative.

4.5 Wi-Fi access

Wi-Fi calling reaches the same IMS through an IPsec tunnel from the UE to an ePDG (4G, via S2b to the PGW) or N3IWF (5G, via N2/N3 to AMF/UPF). The access-network information in IMS signalling then reports the access type as WLAN and may carry the UE's local IP address rather than a cell. Location is therefore absent or unreliable for Wi-Fi-originated sessions, and the public IP seen by the ePDG is the user's broadband address, not a mobile one.

5.3 What the network does not generate

  • Continuous location: only cell identity at signalling moments; RRC_INACTIVE in 5G reduces it further.
  • Content: media is on the user plane and never passes the IMS core; retained records do not and must not contain it.
  • OTT services: a PDU session to a content-delivery network, with the destination increasingly hidden by encrypted DNS, encrypted SNI and QUIC.
  • Who was holding the device.
  • Reliable device identity per session: IMEI/PEI is captured at attach and at IMS registration, not per call.
  • Reliable location for Wi-Fi-originated sessions.

5.4 The 4G/5G migration traps

  • NSA is 4G. A 5G-labelled subscriber on Option 3x produces 4G core and 4G IMS records. No AMF, no SUPI, no NCGI.
  • EPS Fallback splits a call. Registration and INVITE on 5G, bearer and media and release on 4G. Correlate on ICID, not on access type.
  • Cell identity spaces differ. ECGI (28-bit) and NCGI (36-bit) are different identifiers; a cell-site reference table must hold both.
  • IP address behaviour differs. SSC modes 2 and 3 can change the UE address mid-session; multiple PDU sessions per slice multiply addresses per device.
  • Identity concealment. SUCI never appears in clear; records carry SUPI only after UDM de-concealment, so radio-side traces cannot be joined to subscribers without the core.
  • Separate charging functions. OCS/OFCS and CHF may run in parallel with different record formats for years.
  • Feed inventory doubles. Every 4G feed has a 5G counterpart; volume reconciliation must be per feed per generation.

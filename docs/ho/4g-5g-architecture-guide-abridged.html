The ten things to hold in your head

  1. Both generations are all-IP. Every service, including voice, is a packet flow. Voice is delivered by a separate system, the IMS, that sits on top of either core.
  2. Three planes. Control (signalling: who, when, where), user (the traffic itself), management (configuration). Communications data lives on the control plane; content lives on the user plane.
  3. Radio and core are separate. Base stations (eNB in 4G, gNB in 5G) handle the air interface; the core handles identity, sessions, policy and the route to the outside world.
  4. 4G's core is a handful of boxes. MME (control brain), HSS (subscriber database), SGW and PGW (user-plane gateways), PCRF (policy). Point-to-point interfaces with letter-number names.
  5. 5G's core is a set of services. AMF, SMF, UPF, UDM, AUSF, PCF, NRF, NSSF, NEF, CHF — cloud-native functions on an HTTP/2 bus. Control and user plane fully separated.
  6. '5G' may be 4G underneath. Non-standalone 5G (NSA, Option 3x) uses a 5G radio on a 4G core: all records are 4G records. Standalone (SA) is the real thing.
  7. The unit of service is a session with QoS. 4G: PDN connection and EPS bearers with a QCI each. 5G: PDU session with QoS flows with a 5QI each. Voice media is QCI/5QI 1; IMS signalling is QCI/5QI 5.
  8. Identity is layered. Subscription (IMSI/SUPI), device (IMEI/PEI), public number (MSISDN/GPSI), IMS identities (IMPI/IMPU), temporary (GUTI), and an IP address per session. No single one is the person.
  9. Location is a cell at a signalling moment. ECGI (4G) or NCGI (5G), captured when something happens; in idle, only the tracking/registration area. Never a track.
  10. One call, many records. Core, IMS, policy and charging nodes each record part of it. The charging correlation identifier (ICID) is what joins them.

3. Sessions, bearers and QoS

A device with an active data connection has, in 4G, a PDN connection per APN (typically 'internet' and 'ims'), each with a default bearer and possibly dedicated bearers; in 5G, a PDU session per DNN, each carrying several QoS flows in one tunnel. The QoS class decides treatment:

QCI / 5QIUsed forWhy it matters
1Voice mediaIts set-up and release bracket a call's media; corroborates IMS timing
2Video media
5IMS signallingExists from attach on every VoLTE/VoNR device — it means registered, not on a call
6-9Internet trafficWhere data-session and ICR-type records come from

Because each APN/DNN has its own IP address, one device holds several addresses at once; and because most operators run carrier-grade NAT, the public address is shared by hundreds of subscribers. 'The device's IP' is only meaningful as (address, port, time).

6. NSA, SA and the migration traps

NSA (Option 3x)SA (Option 2)
Radio LTE anchor + NR secondaryNR only
Core 4G EPC5G core
Identity IMSI, GUTISUPI/SUCI, 5G-GUTI
Location id ECGINCGI
Voice VoLTEVoNR or EPS Fallback
Records All 4G-shaped5G-shaped, with 4G records for fallback calls
  • A '5G subscriber' on NSA produces nothing but 4G records.
  • EPS Fallback splits one call across two cores: INVITE on 5G, media and release on 4G. Correlate on ICID.
  • ECGI and NCGI are different identifier spaces; hold both in the cell-site reference.
  • 5G UEs can change IP address mid-session (SSC modes 2/3) and hold more sessions per device (slices).
  • RRC_INACTIVE in 5G hides even more mobility from the core than 4G idle did.
  • Every 4G feed gains a 5G twin; reconcile volumes per feed per generation.

7. Where communications data comes from

QuestionGo to
Who holds this number / subscription?HSS / UDM and the CRM — a subscription attribute, valid as at a time
Did a call happen, between whom, when, how did it end?S-CSCF
Where was the device when it did?P-CSCF (P-Access-Network-Info) for IMS events; MME / AMF for core events
Which IP address did they have?PGW / SMF allocation record
Who was behind this public IP:port then?CGNAT translation logs — nothing else
Was the call diverted, barred, conferenced?TAS
Which operator was the other party on?IBCF (inter-operator identifier)
Was it 4G, 5G or Wi-Fi?Access type field in P-Access-Network-Info; MME / AMF context
What was said / what app was used / where they were in betweenNot generated. Content is user plane; OTT is encrypted; location is occasional.

The same lawful-intercept plumbing (ADMF provisioning, POIs in AMF/SMF/UPF/CSCF, MDF2 for events and MDF3 for content) carries both interception and communications data. The separation between the two is administrative — authorisation and provisioning — not physical.
